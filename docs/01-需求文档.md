## 1. 背景

### 1.1 现状

本仓库是 DSH（DeepSeek Harness）的一个插件，把 FoloToy AI Passport（ESP32-C3 掌上设备）
接成 DSH 的随身终端。v1 已实现并在真机跑通过：BLE 连接、分片传输、应用层配对、
任务审批、AI 提问、语音上行、状态推送、余额查询、Web 面板。

v1 的代码量：`lib/` 非测试 8788 行 + 测试 4638 行。

### 1.2 为什么重写

不是"代码难看"，是**定位错了**。

v1 把插件写成了"设备管家"：它替设备决定题干截断到 12 个字、选项截断到 10 个字、
语音结果该发给哪个会话、审批卡片该显示什么摘要。这些决策全部写死在主机侧，
绑在一块 240×320 的屏幕上，换一块屏就得改主机代码。

用户明确指出：

> 「不要考虑具体的设备，这个只是插件功能，目标是支持各种设备，只要符合协议即可」
> 「只要符合蓝牙协议，任何设备都可以接入，设备如何显示，显示哪些是设备的问题。插件只负责实现接口」

因此 v2 的定位是**协议服务端**：定义一套设备无关的蓝牙接口，只提供能力，不做呈现决策。

### 1.3 重写的范围

> 「这次说是重构，其实就是重新实现，现在的只是参考，如果有更优的实现先使用更优的实现」
> 「可以删除现在的实现，重新组织」

v1 代码已整体删除（71 个文件），仅保留 git 历史作为参考。协议**不兼容**旧固件。

## 2. 目标与非目标

### 2.1 目标

| # | 目标 | 衡量方式 |
|---|---|---|
| G1 | 设备能作为 DSH 的副屏常态运行 | 有审批/提问时弹提醒，其余时间显示会话状态 |
| G2 | 用户离开电脑后能审阅 AI 思考过程 | 设备可按需拉取任意会话的思考+工具时间线 |
| G3 | 用户能停止跑偏的会话 | 设备发请求，主机会话被取消并回执 |
| G4 | 用户能用语音输入 | ASR 接口可用，设备自行决定用途 |
| G5 | 设备无关 | 主机侧零呈现决策；换设备不改主机代码 |
| G6 | 能力不退化 | v1 的能力在 v2 均有对应实现（见 §4） |

### 2.2 非目标

| # | 不做 | 理由 |
|---|---|---|
| N1 | 不定义设备如何显示 | 属于固件端 |
| N2 | 不做 AI 偏离预警 | 「不需要告诉，用户自己查看觉得偏离」 |
| N3 | 不做工具执行结果 | 「至于命令执行过程和结果，AI思考过程会有展现」 |
| N4 | 不做 AI 回复**全文** | 会话完成时推送结果正文（FR-PUSH-10），但超 `maxMessageBytes` 时**截断**并置 `truncated=1`；完整正文在电脑上看 |
| N5 | 不做实时流式思考过程 | 按需拉取即可 |
| N6 | 不做时间线持久化 | 内存环形缓冲，会话结束即丢 |
| N6b | 不做结果持久化 | `session.result` 纯推送，不落盘、不补发 |
| N7 | 不做多设备 | 「暂时只支持一个即可」 |
| N8 | 不做链路加密 | 应用层配对是"认领/信任"，非抗窃听认证 |
| N9 | 不做设备端**键盘**文字输入 | 「看 + 停 + 说，不支持写」——此处的"写"指键盘录入文字。设备自身不产生文本，唯一文本来源是 ASR 转写结果，而 ASR 结果可以交给 `session.input`（见 N10） |
| N10 | 不做设备新建会话、不切换模型/工作目录、不发文件 | 只允许向已有会话追加一条文本消息（FR-CTRL-5） |

## 3. 用户与场景

### 3.1 主场景：副屏

大多数时间设备放在桌边，显示当前所有会话的状态：有哪几个会话在跑、哪个在等你审批、
跑了多久、哪个是主会话哪些是子代理。

用户不需要看细节，只需要一眼知道"现在要不要我管一下"。

### 3.2 场景：弹提醒

有工具要审批、或 AI 提问时，设备主动提醒（提示音 + 背光/指示灯）。用户可以在设备上
直接裁决，不必回到电脑。

### 3.3 场景：离开电脑审阅

用户离开电脑，设备上可以看到某个会话最近在想什么、调用了什么工具、命令是什么。
觉得跑偏了，直接停止该会话。

### 3.4 场景：语音

用户按住说话，设备申请 ASR 拿到文本，自己决定怎么用：填进提问的自定义答案、
作为审批回复、或者只显示在屏幕上看看。

### 3.5 会话的主从关系

一个主会话可以有多个子代理会话。设备需要能分辨哪些是主、哪些是子，
因为子代理通常是主会话的辅助工作，不该和主会话平级占位。

## 4. 功能需求

编号规则：`FR-<类别>-<序号>`。优先级：Must / Should / Could。

### 4.1 连接与配对

| ID | 需求 | 优先级 |
|---|---|---|
| FR-CONN-1 | 主机扫描并连接符合协议的设备（广播三选一识别 + GATT 校验） | Must |
| FR-CONN-2 | 连接后协商 MTU，确定单条消息上限并告知设备 | Must |
| FR-CONN-3 | 意外断链自动重连（退避 1/2/5/10/20/30 秒），主动断开不重连 | Must |
| FR-CONN-4 | 重连后重新握手，不沿用旧状态 | Must |
| FR-CONN-5 | 应用层配对：6 位一次性码 → token → 信任表持久化 | Must |
| FR-CONN-6 | token 不匹配时只自动重置一次，避免无限循环 | Must |
| FR-CONN-7 | 保活：连续 30 秒无任何入站帧判定断链 | Must |
| FR-CONN-8 | BLE 原生依赖隔离在子进程，避免拖垮宿主 | Must |

### 4.2 传输层

| ID | 需求 | 优先级 |
|---|---|---|
| FR-XFER-1 | 单条消息分片传输，最多 16 片 | Must |
| FR-XFER-2 | 接收端重组，缺口整条丢弃并回 `nack` | Must |
| FR-XFER-3 | 控制通道支持 ACK + 重传（指数退避 400/800/1600ms） | Must |
| FR-XFER-4 | 支持选择性重传（只补缺失分片） | Should |
| FR-XFER-5 | 音频通道按到达顺序追加，不重组/不去重/不排序 | Must |
| FR-XFER-6 | 消息号 12 位环形分配，所有路径必须释放 | Must |
| FR-XFER-7 | 超上限载荷直接拒绝并报错，不静默截断 | Must |

### 4.3 推送（主机 → 设备）

| ID | 需求 | 优先级 |
|---|---|---|
| FR-PUSH-1 | 推送会话集合全量快照，含 `role: main\|sub` 与 `parentId` | Must |
| FR-PUSH-2 | 快照带单调递增 `ver`，设备只接受更新的版本 | Must |
| FR-PUSH-3 | 快照超上限时按 `part/parts` 拆分 | Must |
| FR-PUSH-4 | 推送审批请求，含全文（工具名、原因、本地化原因、关键参数） | Must |
| FR-PUSH-5 | 审批结束时推送 `approval.done`（含被电脑端抢先处理） | Must |
| FR-PUSH-5b | 审批无论由设备还是电脑端裁决，结束都必须推送 `approval.done`，设备据此收起卡片 | Must |
| FR-PUSH-6 | 推送提问请求，整批下发，题干/选项/描述全文 | Must |
| FR-PUSH-7 | 提问结束时推送 `question.done` | Must |
| FR-PUSH-8 | 推送提示（文本、紧急标志、提示音开关） | Should |
| FR-PUSH-9 | 状态变化即推，主机侧做内容级去重 | Must |
| FR-PUSH-10 | 会话本轮完成时推送 `session.result`（回复正文 + 结局 + 耗时 + 完成时刻），即使电脑前无人也要发 | Must |
| FR-PUSH-11 | `session.result.text` 超单条消息上限时截断并置 `truncated=1`，设备据此提示"去电脑看全文" | Must |
| FR-PUSH-12 | `session.result` **不落盘**：主机只保留"已推送过的 turnId"内存去重集合，不写文件、不跨重启补发 | Must |

### 4.4 拉取（设备 → 主机）

| ID | 需求 | 优先级 |
|---|---|---|
| FR-PULL-1 | 设备可主动拉取会话集合（不等推送） | Should |
| FR-PULL-2 | 设备可按数量拉取某会话最近的思考+工具时间线 | Must |
| FR-PULL-3 | 时间线合并为一条序列，每条带递增 `seq` | Must |
| FR-PULL-4 | 工具条目只含工具名 + 一个关键字段 | Must |
| FR-PULL-5 | 条目整条保留，装不下时整条丢弃并如实报告 `dropped` | Must |
| FR-PULL-6 | 环形缓冲按会话隔离，默认保留最近 20 条 | Must |
| FR-PULL-7 | 时间线不落盘、不跨重启、会话结束即丢 | Must |
| FR-PULL-8 | 余额查询（取不到时报错，不伪造 0） | Could |

### 4.5 ASR

| ID | 需求 | 优先级 |
|---|---|---|
| FR-ASR-1 | 设备发送音频，主机返回文本 | Must |
| FR-ASR-2 | 接口无状态、无副作用，不绑定会话 | Must |
| FR-ASR-3 | 支持 30 秒音频，编码固定为 `ima-adpcm`（4 字节块头 + 504 字节数据，低 nibble 先，状态跨块保持） | Must |
| FR-ASR-3b | 不支持 `pcm16`：30 秒 PCM 需 938KB，实测 15–17KB/s 传不完；收到 `codec:"pcm16"` 回 `ASR_FAILED` 不降级 | Must |
| FR-ASR-4 | 空文本是正常结果（听到但没识别出），不是错误 | Must |
| FR-ASR-5 | 失败时回明确错误码与可显示的消息 | Must |
| FR-ASR-6 | 主机不自动把文本注入任何会话 | Must |
| FR-ASR-7 | 设备可主动取消在途转写，主机丢弃已收音频且不回执 | Should |

### 4.6 控制（设备 → 主机）

| ID | 需求 | 优先级 |
|---|---|---|
| FR-CTRL-1 | 设备可请求停止某个会话，主机回执成功/失败与原因 | Must |
| FR-CTRL-2 | 设备可对审批裁决（允许/拒绝） | Must |
| FR-CTRL-3 | 设备可对提问作答（提交/取消/拒绝），含自定义输入 | Must |
| FR-CTRL-4 | 停止会话无特殊延迟要求，走普通请求-应答 | Must |
| FR-CTRL-5 | 设备可向**已有会话**追加一条用户消息（`sessionId` 必填，主机不猜），会话无论处于 running/done/idle 都接受 | Must |

### 4.7 宿主集成

| ID | 需求 | 优先级 |
|---|---|---|
| FR-HOST-1 | 拦截 `approval/request` 瀑布，设备与电脑端**同时呈现、先答者胜**，不抑制任何一端 | Must |
| FR-HOST-2 | 拦截 `user-questions/request`，允许设备与电脑竞速作答 | Must |
| FR-HOST-3 | 订阅会话事件，维护会话集合与时间线 | Must |
| FR-HOST-4 | 提供 4 个 Agent 工具（状态/通知/询问/余额） | Should |
| FR-HOST-5 | 提供 Web 控制面板（回环限定） | Could |
| FR-HOST-6 | 提供桌面挂件，仿照 v1 现有形式：链路胶囊（状态点+文字+关注角标）、设备信息区（固件/电量/信号/握手 + 断开/诊断）、配对码输入区、ASR 服务状态区（是否可用 + 准备模型） | Should |
| FR-HOST-7 | 插件加载失败不得影响宿主启动 | Must |

## 5. 边界与约束（硬性）

这些不是建议，是实现时必须遵守的约束。违反即视为设计错误。

| ID | 约束 | 来源 |
|---|---|---|
| C1 | 主机侧**不得截断**任何人读文本（题干、选项、原因、命令等） | 「截断是设备的呈现决策」 |
| C2 | 主机侧**不得**替设备决定内容去向（不猜会话、不自动注入） | ASR 边界 |
| C3 | 主机侧**不得**硬编码屏幕尺寸相关的数值 | 设备无关 |
| C4 | 单条消息上限由设备声明 + 主机按 MTU 确定，不写死 | 设备无关 |
| C5 | 所有等待设备响应的状态必须有断链清理路径 | v1 缺陷 |
| C6 | 音频通道不得做重组/去重/排序 | v1 缺陷 |
| C7 | 保活判定必须基于"任意入站帧"，不是只看 pong | v1 缺陷 |
| C8 | 插件不得在对象上写 `inject: [...]`（会推迟整个 apply） | DSH 加载模型 |
| C9 | 插件加载失败必须被捕获，不得让宿主起不来 | 真实事故 |
| C10 | BLE 原生依赖不得在宿主进程内加载 | 真实事故 |
| C11 | 协议不兼容旧固件，版本不符即拒绝并明确报错 | 「不必兼容现在的」 |

## 6. 非功能需求

| ID | 需求 | 目标值 |
|---|---|---|
| NFR-1 | 状态推送延迟 | 变化发生后 ≤ 1 次心跳周期（5s）内送达 |
| NFR-2 | 会话状态载荷大小 | 典型 10 会话 < 2KB，单条消息内 |
| NFR-3 | 时间线拉取延迟 | 拉取 20 条 ≤ 1 秒（链路空闲时） |
| NFR-4 | 录音上行 | 30 秒 ADPCM = 241908 字节 ≈ 236KB（476 满块 + 1 尾块），速率 7.87KB/s |
| NFR-4b | 链路带宽预算 | 实测有效吞吐 15–17KB/s；ADPCM 占 46%–52%，余量留给控制通道 |
| NFR-5 | 会话取消响应 | 无硬性要求，链路忙时排队数百毫秒可接受 |
| NFR-6 | 内存占用 | 每会话 ≤ 20 条时间线，总占用可控 |
| NFR-7 | 插件启动 | 不得阻塞宿主启动；autoConnect 异步执行 |
| NFR-8 | 测试覆盖 | 协议层与传输层必须可脱离真实 BLE 测试 |

## 7. 能力对照（v1 → v2）

重构要求"能力不能少，行为可以变"。逐项对照：

| v1 能力 | v2 实现 | 变化 |
|---|---|---|
| 扫描/连接/重连 | FR-CONN-1..4 | 保留 |
| MTU 协商 | FR-CONN-2 | 保留，改为主动告知设备 |
| 分片重组 + ACK 重传 | FR-XFER-1..3 | 保留，重传改指数退避 |
| 应用层配对 | FR-CONN-5..6 | 保留 |
| 审批允许/拒绝 | FR-PUSH-4/5 + FR-CTRL-2 | **载荷从摘要改为全文** |
| AI 提问（单选/多选/自定义） | FR-PUSH-6/7 + FR-CTRL-3 | **整批下发，全文** |
| 语音上行 → 转写 | FR-ASR-1..6 | **从"语音管家"降为纯 ASR 服务** |
| 状态推送 | FR-PUSH-1..3 | **从聚合单态改为会话集合** |
| 余额显示 | FR-PULL-8 | 保留，删除恒为 null 的"今日已用" |
| 提示音/背光/toast | FR-PUSH-8 | 保留，取消 120 字截断 |
| Web 面板 | FR-HOST-5 | 降级为 Could，去死界面 |
| 4 个 Agent 工具 | FR-HOST-4 | 保留，修 `ap_device_ask` |
| 桌面挂件 | FR-HOST-6 | 保留现有形式；仅删除「语音结果自动填草稿」（ASR 结果不再回主机） |
| —— | FR-PULL-2..7 | **新增：思考过程与工具时间线** |
| —— | FR-CTRL-1 | **新增：停止会话** |

### 7.1 明确的体验损失

以下 v1 体验在 v2 中**不存在**，需要用户知情：

| 损失 | 原因 |
|---|---|
| 对着护照说话，字自动落进电脑**输入框草稿** | ASR 结果只回给发起方（设备）。设备可以用 `session.input` 把文本作为一个**用户消息发进会话**，但那不是"填进电脑的输入框等着编辑"——没有草稿态，发出即提交 |
| 设备上浏览/新建/切换任务列表 | 用户裁决"看 + 停 + 说"，不含切换 |
| 工具调用结果与 AI 回复正文（**全文**） | 会话完成时推 `session.result` 给正文，但超 `maxMessageBytes` 会截断（`truncated=1`），完整正文需回电脑看 |
| 断链期间完成的会话拿不到回复正文 | `session.result` 是一次性推送，断链即丢不补发；重连后只能从 `session.state` 看到"已完成" |
| 子代理会话合并进主计数 | 改为逐条列出（这是修复，不是损失） |

## 8. 验收标准

### 8.1 功能验收

| # | 场景 | 通过条件 |
|---|---|---|
| A1 | 设备上电连接 | 30 秒内完成握手，`paired` 状态正确 |
| A2 | 首次配对 | 设备显示 6 位码，电脑输入后配成，重连不再要求配对 |
| A3 | 会话状态 | 主会话起 3 个子代理，设备收到 4 条会话条目且 `role` 正确 |
| A4 | 审批全文 | 设备收到完整工具名与原因，不是 12 字摘要 |
| A5 | 审批双端呈现 | 设备在线时电脑卡片照常弹出，两端同时可见 |
| A5c | ASR 取消 | 设备发出 `asr.cancel` 后主机丢弃在途音频、不回任何消息；同 `requestId` 下次录音不混入旧字节 |
| A5d | 会话续接 | 设备对 `done` 状态的会话发 `session.input`，`ack.ok=true` 且该会话 `state` 变回 `running`，新一轮产出正常 |
| A5b | 裁决通知终端 | 电脑端先批，设备在 1 秒内收到 `approval.done{decidedBy:"pc"}` 并收起卡片；反之亦然 |
| A5e | 会话完成推结果 | 会话跑完时设备收到 `session.result`，含本轮回复正文、`state`、`elapsedMs`；同 `turnId` 只收一次 |
| A6 | 提问全文 | 设备收到完整题干、全部选项与描述 |
| A7 | 提问自定义 | 设备用 ASR 拿到文本，填入 `custom` 提交成功 |
| A8 | 思考拉取 | 拉 20 条，返回按 `seq` 升序，含 reasoning 与 tool 两类 |
| A9 | 工具关键字段 | bash 条目带完整 command，write 条目带 path，未知工具只有名字 |

## 11. 术语

| 术语 | 含义 |
|---|---|
| 插件 / 主机 | 本仓库，跑在 DSH 宿主里的 npm 包 |
| 设备 | 符合本协议的蓝牙外设，当前实现是 FoloToy AI Passport |
| 会话 | DSH 里一个 agent 执行上下文，有主从关系 |
| 时间线 | 某会话的思考过程 + 工具调用，按序号排列 |
| 推送 | 主机主动发，设备被动收 |
| 拉取 | 设备发请求，主机应答 |
| 关键字段 | 工具调用中唯一有意义的那一个参数（bash→command、write→path 等） |
| 竞速 | 审批与提问均同时在电脑和设备上呈现，先答者胜；落败方由 `approval.done` / `question.done` 通知收起 |
